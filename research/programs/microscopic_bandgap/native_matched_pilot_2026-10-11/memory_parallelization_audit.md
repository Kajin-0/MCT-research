# Source-grounded memory and parallelization audit — 2026-10-11

**Scope: read-only investigation, not a new SCF authorization.** Verified native QE 7.5 failed-host stdout, input, 354 telemetry samples, launch monitor and the publicly available QEF/q-e `qe-7.5` EXX source. No DFT job, supervisor, tmux or persistent-goal modification. Previous host failure and Cd rejection remain terminal.

## Root cause

- The original native job used 6 MPI ranks × 1 OpenMP thread, `-nk 1`, `-nb 1`, a 16-atom noncollinear/SOC cell, 352 bands, an EXX 2×2×2 q mesh, and f120 HSE. Its actual EXX FFT dimensions were **64×64×64** (not the dense 108³ charge grid); stdout explicitly states **8 k+q points** and `ACE projected onto 352 (nbndproj) and applied to 352 (nbnd) bands`.
- Native `pw.out` recorded 6 inner SCF iterations and then `Using ACE for calculation of exact exchange`. The saved telemetry's MPI-family RSS was roughly 6.4 GiB at 612 s, 15.24 GiB at 652 s and **26.722 GiB at 731.37 s**. Concurrent MemAvailable declined from 29.322 to **2.766 GiB**; the configured process-family RSS cap was **26.640 GiB** and the 4-GiB soft free-memory threshold had also been crossed. The stop is real; full HSE-SCF peak remains unknown.
- QE **7.5** `PW/src/exx.f90`, routine `exxinit`, in its nonlocalized EXX branch allocates `exxbuff(nrxxs*npol, max_buff_bands_per_egrp, nkqs)` (approximately lines 545–552). `nrxxs` is local EXX FFT storage, `npol=2` for spinors, `nkqs=8`, with up to 352 buffered bands in the sole exchange band-group; each entry is a 16-byte complex double. Before layout padding and redistribution, this array's **aggregate nominal capacity** is:

  `(64^3 FFT sites) × (2 spinor components) × (352 bands) × (8 q points) × (16 bytes) = 23,622,320,128 bytes = 22.000 GiB`.

  This is a **source-conditioned allocation model**, not a measured private-memory breakdown or rigorous bound on resident memory. FFT padding, band-group partitioning, symmetries, other EXX, ACE projector `xi`, wavefunction and MPI allocations affect total peak; untouched virtual allocation might not be fully resident. Nevertheless 22 GiB is a plausible dominant cause of the abrupt >20-GiB rise.
- The QEF source also allocates `xi(npwx*npol,nbndproj,nks)` for ACE (`exx.f90`, `aceinit`) and exchange wavefunction transport arrays. Lowering `nbndproj` in SCF is **not** a free input knob: `exxinit` sets `nbndproj=nbnd` by default. Changes to 352-band coverage, q grid, Fock cutoff or localization model would alter the calculation or validation obligation.

## Optimization decisions before any further native job

1. **Do not assume `pw.x -nband 2` automatically halves RAM.** In `exx.f90` the same EXX buffer scales as `nrxxs × bands_per_group × nkqs`; splitting six ranks into 2 band groups of 3 can approximately double local FFT storage and halve bands per group, *leaving about 22 GiB aggregate capacity*. For 3 groups of 2 ranks the nominal capacity is also about 22 GiB (plus rounding). Band-group partitioning improves exchange parallel work allocation, but memory saved in other arrays or new replicas/communication are unmeasured.
2. **Changing to fewer MPI ranks or hybrid OpenMP does not intrinsically remove the 22-GiB exchange-buffer workload.** It can reduce duplicated process-level overhead but changes each rank's local FFT geometry, communication and working set. QE 7.5 compiled with MPI/OpenMP libraries is not proof that a given mixed-mode decomposition will be faster or fit safely. A `-np 3, OMP_NUM_THREADS=2` candidate is unvalidated and must not run as an automatic fallback.
3. **Task groups and k-point pools are not reliable memory-removal solutions here.** The native `pw.out` has only 3 irreducible k-points, and FFT/task/linear-algebra groups distribute different data structures. Reducing q mesh/bands/cutoffs, enabling orbital localization/SCDM or patching QE to stream q buffers may reduce memory but changes numerical physics or software algorithms and demands separate validation; do not silently choose one.
4. **Instrument a future explicitly authorized short ACE-stage benchmark**, if one can be justified: record `/proc/<rank>/smaps_rollup` PSS/USS/Private_Dirty (rather than summed RSS alone), `/proc/meminfo` MemAvailable, per-rank VSZ/RSS and FFT/band-group metadata, cgroup events, file backing/swap, and a strict abort before unsafe memory pressure. Ensure identical deck/PP/source hashes and a unique output directory. This is **a new native run** and is *not authorized by this audit*.
5. Given an already observed >26-GiB RSS at an unfinished ACE stage, **32 GiB is not qualified** for the full matched HSE experiment. With preserved physics and no validated memory-saving QE change, a machine with materially more RAM (e.g. 64 GiB as an engineering starting point, not a measured bound) is presently the lower-risk route. A successful pilot still does not determine physical alloy x_c.
